BUG-04
Title: Audit API returns 401 for valid access tokens on staging
Priority: Highest (blocker)
Story: blocks CSP-250, CSP-252, CSP-253
Status: open on sellora-audit dev 770ccad
Steps: 1. Copy a fresh Company Admin access token from the web app. 2. GET https://sellora-audit-staging-egdwdxbnexg4hadk.eastasia-01.azurewebsites.net/api/audit?pageSize=1 with Authorization: Bearer <token>. 3. Send the same token to GET /api/deliveries on the Delivery API.
Expected: 200 from both.
Actual: Delivery answers 200; Audit answers 401 with an empty body (the service's own JWT check, not API Manager). Every role gets the same 401 on /api/audit, /api/audit/verify, /api/reports/* and /api/reports/export, so no audit, report or export case can run.
Likely cause: the same as BUG-01 in Delivery. Program.cs relaxes the certificate check for the WSO2 IS metadata call only when the environment is Development or Staging. The repo has no appsettings.Staging.json and cd-staging.yml sets no app settings, so if ASPNETCORE_ENVIRONMENT is not Staging on the sellora-audit-staging App Service, the service cannot download the signing keys from https://13.61.228.129:9443 (self-signed certificate) and rejects every token. The App Service log stream should show IDX20803 "Unable to obtain configuration".
Suggested fix: set ASPNETCORE_ENVIRONMENT=Staging on the sellora-audit-staging App Service (or add it to the deployment), restart, and check the log stream.
Also needed: publish the Audit API in API Manager (context /sellora-audit/1.0.0) and subscribe the web app's application, so the tests and the web app go through the gateway like the other services. The QA run used the App Service URL directly because the gateway path answered 404.
Retest: fresh tokens, python audit_log_tests.py --target staging. The preflight line must show "Audit GET /api/audit -> 200"; then rerun CSP-250, CSP-252 and CSP-253.
